# ساده‌سازی کار منشی و مدیریت سایت

این تغییر پس از ادغام موردتأیید PR #15، روی شاخه مستقل feat/clear-secretary-admin-workflows انجام می‌شود. ادغام این شاخه نیازمند بررسی بعدی مالک است. دامنه: NFR-01، FR-SRV-01، FR-SCH-01/02، FR-REP-01/02، FR-FRM-01، FR-DIS-01 و مدیریت Website/CMS موجود.

## تغییرات قابل بررسی

- خدمات، مقالات، بخش‌ها و پیوندهای سایت: فهرست خلاصه با عنوان/وضعیت، ویرایش قابل بازکردن، ساخت مورد جدید جدا، جستجوی فوری محلی با شمارش نتیجه. جستجو صریحاً فقط همان صفحه فعلی را پوشش می‌دهد؛ pagination سرور حفظ شده است.
- نمایش نام، تعرفه/مدت و وضعیت خدمت پیش از بازکردن فرم. تغییر قیمت/ظرفیت همچنان فقط از درخواست اصلی و قواعد سرور می‌گذرد.
- مدیریت سایت: راهنمای رفتن به بخش دیگر، انتخاب هویت/محتوا، صفحه‌ساز، مقالات، منو و بخش‌ها؛ در موبایل جمع‌شونده. لینک بخش‌های فاقد مجوز نمایش داده نمی‌شود. سایت عمومی در برگه جدا باز می‌شود.
- صفحه‌ساز: مسیر ویرایش ← ذخیره پیش‌نویس ← پیش‌نمایش/انتشار؛ فهرست صفحه‌ها تفاوت نسخه عمومی و تغییر ذخیره‌شده منتشرنشده را بیان می‌کند. انتشار خودکار اضافه نشده است.
- مدیریت خدمات سایت: متن و تصویر در کارت‌های جدا، دوستونه دسکتاپ/تک‌ستونه موبایل. حذف/آپلود تصویر و انتشار خصوصی/عمومی قبلی حفظ شده‌اند.
- میز کار منشی: جستجوی روز/مراجع با عنوان و راهنمای روشن. برنامه معمول هفته و تعطیلی/ساعات ویژه یک بازه جدا هستند. فیلدهای ساعت برای روز تعطیل پنهان می‌شوند ولی مقادیر پاک یا از payload حذف نمی‌شوند؛ قرارداد حاضر بودن shifts در سرور حفظ می‌شود.
- گزارش: انتخاب نوع و بازه در کارت اول، خلاصه و خروجی‌ها در کارت جدا. در انتخاب گزارش مالی، فیلترهای مخصوص نوبت پنهان و disabled می‌شوند؛ با بازگشت به نوع نوبت، مقادیر قبلی برمی‌گردند. بررسی مجوز و اعتبارسنجی سرور همچنان مستقل‌اند.
- مالی: پیگیری پرداخت و استرداد در کارت‌های جدا؛ تنظیم اختلال درگاه بخش جدا دارد. فرم‌ها، سیاست رزرو، تخفیف و اعلان‌ها نیز گروه‌بندی شده‌اند. زمان پیگیری پیامک و پایان سیاست اضطراری به شمسی/تهران نمایش داده می‌شود؛ ذخیره UTC تغییر نکرده است.

## خطای فرم و حفظ ورودی

صفحه‌های دارای چند فرمِ هم‌نام، شناسه نمایشی _ux_context می‌فرستند. این مقدار فقط برای بازکردن و نمایش خطای همان ویرایشگر است؛ مجوز، رکورد مقصد، قواعد انتشار یا محاسبات را تعیین نمی‌کند و وارد داده validated کسب‌وکار نمی‌شود. نمایش خطا به input همان فرم متصل می‌شود؛ پنل بسته لازم باز می‌شود. ورودی ناموفق یک مقاله/خدمت/پیوند در فرم‌های دیگر کپی نمی‌شود. UiInput فقط scalar و فهرست انتخاب ساده را برای نمایش بازیابی می‌کند؛ شکل‌های نامعتبر آرایه‌ای باعث اجرای HTML یا خطای رندر نمی‌شوند. نوع استثنای برنامه و ساعت نامعتبر برای اصلاح حفظ می‌شوند.

فرم‌های ویرایشی قابل جمع‌شدن هشدار خروج با تغییر ذخیره‌نشده دارند. فیلتر محلی و بازکردن پنل تغییر ذخیره‌نشده محسوب نمی‌شوند. تأیید حذف و قواعد ارجاع تصویر، CSRF، نسخه و idempotency قبلی حذف نشده‌اند. برای کاربران بدون JS، details و فرم‌های اصلی همچنان کار می‌کنند؛ جستجوی فوری و بهبود focus افزوده JS هستند. اطلاعات بیمار در URL، storage مرورگر یا داده فیلتر مدیریت اضافه نشده است.

## معماری و مرزها

Blade، اجزای work-record / record-tools / website-workflow، CSS محلی workflow.css، Vanilla JS محلی workspace-ux.js و helper نمایشی UiInput. بدون کتابخانه یا CDN جدید، endpoint جدید، migration، تغییر نقش یا تغییر سیاست رزرو/پرداخت/استرداد/پیامک. بانک و SMS زنده و تست نفوذ انسانی مستقل در این کار نیستند.

## آزمون و تحویل

Feature: بازیابی فقط فرم ردشده، بازماندن همان پنل، حفظ رکوردهای دیگر/قیمت، URL مخرب، شکل نامعتبر old input، مجوزهای منشی، حفظ نوع استثنا و داده نامعتبر ساعت، عدم افشای دریافت‌کننده/پارامتر پیامک با نمایش تاریخ تهران.

مرورگر: ماتریس ۳۳ مسیر در ۳۲۰/۷۶۸/۱۴۴۰ پیکسل به‌علاوه تعامل جستجوی محلی، خطای واقعی سرویس دوم و اصلاح/ذخیره، پیوند خطا و focus، صفحه‌کلید ویرایشگر، ساخت مورد جدید، منوی مدیریت موبایل، تعطیلی منشی بدون پاک‌کردن ساعت، و فیلتر مالی بدون ارسال فیلد نامرتبط. نتیجه دقیق PHP/MySQL/مرورگر/ZIP/اسکن و تصاویر در PR و CI همان commit ثبت می‌شوند؛ بررسی با کاربران واقعی کم‌تجربه همچنان مرحله بازخورد مالک است.

در ارتقا .env، APP_KEY و storage خصوصی حفظ شوند. پس از پشتیبان‌گیری، php artisan migrate --force و php artisan optimize:clear اجرا شوند؛ این شاخه migration جدید ندارد. بسته نهایی main مربوط به PR #15 از CI main خودش دریافت شود؛ بسته این شاخه آزمایشی و جداست.

نتیجه محلی نسخه تحویلی: ۳۰۶ تست PHP با ۲۲۴۷ assertion موفق؛ ۹ تست مرتبط بسته‌بندی/رابط با ۵۴ assertion نیز پس از هماهنگ‌کردن راهنمای ZIP موفق بودند. Pint و syntax JS موفق. ۲۹ سناریوی Chromium و ۹۹ بررسی مسیر/اندازه موفق؛ بدون خطای JS، نقض CSP، درخواست منبع خارجی یا فایل ظاهری ناموفق. ساخت/نصب و MySQL/اسکن دقیق به CI همان commit در PR ارجاع داده می‌شوند.

## اصلاح فوکوس ایجاد رکورد در PR #18

بازکردن فرم از لینک `data-open-record` باید پیش از پایان رویداد فعال‌سازی، اولین فیلد را فوکوس کند. handler قبلی فوکوس را با requestAnimationFrame عقب می‌انداخت و ناوبری پیش‌فرض fragment نیز فعال بود؛ در نتیجه زمان‌بندی مرورگر می‌توانست فوکوس عنوان مقاله را از دست بدهد. handler اکنون پس از شناسایی پنل معتبر، رفتار پیش‌فرض را لغو می‌کند، details را باز می‌کند و مستقیماً فیلد را فوکوس می‌کند. fallback بدون JavaScript همچنان لینک و details بومی است.

هیچ assertion قبلی حذف یا ضعیف نشد. تست CMS یک بررسی اضافی در خود رویداد click دارد تا فوکوس هم‌زمان را الزام کند و با تأخیر تصادفی سبز نشود. آزمایش مقایسه‌ای با محتوای اصلی workspace-ux.js مشکل را در هر چهار ترکیب کلیک/Enter و عرض ۳۲۰/۱۴۴۰ بازتولید کرد؛ کد اصلاح‌شده در همان چهار حالت موفق شد. این اصلاح فقط رفتار رابط بازکردن رکورد را تغییر می‌دهد و داده، endpoint و قواعد رزرو را تغییر نمی‌دهد.

اعتبارسنجی محلی اصلاح فوکوس: مجموعه کامل ۲۹ سناریوی controls.mjs همراه assertion جدید، ۳۲۰ تست PHP با ۲۳۸۵ assertion، Pint، node --check هر دو فایل JavaScript و git diff --check موفق شدند. نتایج اجرای GitHub CI به commit اصلاحی همین PR وابسته‌اند.
