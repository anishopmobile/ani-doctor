MySQL آزمون در یک data directory جدید و جدا از دیتابیس مطب، فقط روی loopback/پورت 33317 و دیتابیس `ani_doctor_test_bale` اجرا شد. داده‌ها، کارت، حساب‌ها، کلید و توکن همه ساختگی‌اند. credential دیتابیس واقعی استفاده نشد.

رقابت‌های جدید: انتخاب کارت در برابر شروع زرین‌پال فقط یک روش فعال می‌سازد؛ دو ارسال رسید روی یک hold فقط یک قطعی‌سازی ایجاد می‌کنند؛ دو تأیید هم‌زمان فقط یک پرداخت ایجاد می‌کنند. تست از barrier و انتظار واقعی قفل InnoDB استفاده می‌کند. رقابت‌های مالی قبلی نیز در همان اجرا موفق شدند.

مرورگر: امضای initData ساختگی ولی بررسی واقعی سرور، بدون وابستگی به cookie؛ انتخاب بیمار خانواده/خدمت/ساعت؛ رزرو مشترک؛ رسید واقعی فایل در DB آزمایشی و confirmed/card_pending؛ ارسال مدرک و پاسخ‌های دارای مالکیت؛ رد امضای دستکاری‌شده؛ صندوق منشی و بررسی اندازه‌های نمایش. API بله و سفیر واقعی در این آزمون فراخوانی نشدند.

تصاویر و summary آزمون مرورگر در مسیر deliverables/bale-browser در workspace موجودند؛ داده واقعی ندارند و جزو بسته نصب نیستند.

## CI آنلاین و وضعیت انتشار

Workflow موجود برای اجرای آزمون مرورگر جدید بله به‌روزرسانی شده است؛ مراحل قبلی PHP، MySQL، هم‌زمانی، مرورگر، dependency audit و بسته‌بندی حفظ شده‌اند.

CI آنلاین هنوز اجرا نشده است: بررسی خودکار مجوز، push به GitHub را به دلیل نبود تأیید صریح مقصد خارجی متوقف کرد. درخواست اجازه ارسال **فقط شاخه feature/bale-integration به anishopmobile/ani-doctor** و ساخت پیش‌نویس بازبینی مطرح شده است. تا دریافت این تأیید، هیچ push/PR انجام نمی‌شود و هیچ نتیجه CI آنلاین موفق ادعا نمی‌شود.

محدودیت‌های باقی‌مانده: credential و دسترسی واقعی سفیر/بازو، آزمون روی نسخه‌های واقعی Android/Web بله و دامنه HTTPS استقرار، اسکن بدافزار و پایش فایل orphan/outbox؛ صف manager_review هنوز تصمیم مالی انسانی مدیر می‌خواهد و نوبت گذشته/حضور را خودکار حذف نمی‌کند. این خروجی آماده بازبینی توسعه است، نه مجوز انتشار تولید. قرارداد و راه‌اندازی: BALE-INTEGRATION.md؛ هشت قابلیت آینده: BALE_BACKLOG.md.
