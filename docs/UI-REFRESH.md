# بازطراحی رابط و کنترل‌های فرم
دامنه: درخواست کاربر برای Tabler در هر دو فضای مدیریت/کاربری، ظاهر SaaS آبی/Soft UI/RTL/mobile-first، تاریخ‌گزین شمسی برای ورودی تاریخ و select دارای جستجوی داخلی. مرتبط با NFR-01، FR-CAL-01، FR-REP-02 و UI_GUIDELINES. این تغییر روی شاخه feat/tabler-rtl-ui-controls است و تا پذیرش کاربر merge نمی‌شود.

## معماری و سازگاری
- Blade SSR و Service Layer حفظ شده؛ route، API، policy، قواعد پول/رزرو/OTP/پرداخت و schema تغییری نکرده‌اند.
- Tabler RTL 1.4.0 موجود، تنها CSS پایه برای تمام کاربران است؛ Bootstrap از داخل Tabler تأمین می‌شود. بارگذاری CSS مجزای Bootstrap تکراری حذف شده است. منوی مشترک در app-navigation با can/canany، نسخه sidebar و منوی details موبایل ارائه می‌شود.
- app.css فقط پوسته بصری و controls.css فقط کنترل‌های نام‌گذاری‌شده است. فونت محلی Vazirmatn و CSP بدون تغییر است؛ هیچ CDN/runtime، npm build، jQuery یا Vite در اپ/هاست لازم نیست.
- برای تاریخ‌ها Pardis فعلی با مجوز MIT دوباره استفاده شده؛ گزینه پیشنهادی باباخانی به jQuery و persian-date وابسته است. یک dialog مشترک با موتور Pardis inline، انتخاب از صفحه‌کلید و Escape/بستن؛ نام فیلد و مقدار yyyy-MM-dd شمسی حفظ می‌شود. تقویم رزرو و AJAX موجود مستقل و همیشه inline می‌مانند. تاریخ hidden فوری منشی که سرور تولید می‌کند، تاریخ انتخابی کاربر نیست.
- hcg-searchable-select 1.0.4 از commit ثابت 081f8e76033b600cc761af849bef8b1075f20722 به‌صورت محلی، بدون تغییر upstream و همراه MIT استفاده شده است. تک‌انتخابی‌ها از همین کتابخانه‌اند؛ چون upstream multiple را پشتیبانی نمی‌کند، چندانتخابی یک companion کوچک با جستجو و checkbox دارد و select اصلی چندمقداری باقی می‌ماند.
- نام، مقدار و required/disabled فرم‌ها حفظ می‌شوند. تغییر value و گزینه‌های AJAX/فرم‌ساز روی کنترل منعکس می‌شود. fieldset غیرفعال، فیلد شرطی و reset رعایت شده‌اند. جستجو با textContent/escape و بدون eval یا HTML داده کاربر است. پاک‌کردن انتخاب، بازگشت به گزینه اول خالی (همه/انتخاب کنید) است.
- با JS خاموش select و input اصلی قابل استفاده می‌مانند؛ رزرو AJAX و نمایش شرطی مانند قبل JS می‌خواهند. اعتبارسنجی و مجوز سمت سرور منبع حقیقت‌اند. انتخابگر و dropdown در خروجی PDF/Excel وارد نمی‌شوند؛ چاپ گزارش layout مستقل دارد.

## دریافت و بررسی
از artifact موفق همین شاخه، ZIP داخلی کامل همراه vendor را دریافت کنید. قبل از به‌روزرسانی سرور/زمان‌بند را متوقف و پشتیبان بگیرید؛ .env، APP_KEY، DB و storage خصوصی را حفظ کنید. برای این تغییر migration یا dependency جدید وجود ندارد. فایل‌های جدید را همراه فایل‌های تغییرکرده کپی کنید و سپس config:clear، route:clear و view:clear اجرا و سرور/زمان‌بند را باز کنید. refresh کامل مرورگر برای assetهای تازه لازم است. روی داده واقعی PHPUnit یا fixture اجرا نکنید.

## تست مرورگر
tests/Support/ui-fixture.php فقط با UI_SYNTHETIC_FIXTURE=1، SQLite با نام ui-preview.sqlite و providerهای واقعی خاموش اجرا می‌شود. هیچ OTP/داده واقعی لازم نیست. تست tests/Browser/ui-controls.cjs به Playwright 1.62.1 (صرفاً ابزار تست، خارج وابستگی اپ) نیاز دارد. CI آن را در RUNNER_TEMP نصب می‌کند؛ نصب هاست npm/Node نمی‌خواهد. محیط تست از .env نصب مستقل است.
سناریوها: ورود واقعی OTP آزمایشی برای مدیر/منشی/بیمار، ۷ صفحه در ۴ عرض 320/390/768/1440، منوی مجاز نقش‌ها، تاریخ و FormData، select جستجو/کیبورد/reset/programmatic/AJAX، انتخاب ساعت از تقویم inline، فرم‌ساز پویا، چندانتخابی، فیلد تاریخ شرطی، fieldset disabled، برچسب HTML مخرب، CSP/خطای JS و fallback بدون JS. fixture فقط داده ساختگی دارد.

## شواهد و محدودیت
نتایج نهایی در PR و Actions ثبت می‌شوند. نخستین اجرای backend پس از بازطراحی: 230 تست / 1563 assertion موفق؛ مرورگر Edge 156 محلی، نسخه نخست suite با 45 بررسی موفق. خطای اولیه suite درباره URL تقویم و فرض multiple در صفحه تخفیف اصلاح شد؛ multiple روی فرم خصوصی واقعی آزمایش می‌شود. تداخل واقعی blur و حذف گزینه قبل از click اصلاح و تست آن حفظ شد. screenshotهای دسکتاپ و موبایل به‌صورت بصری بررسی شدند؛ دستگاه فیزیکی، Safari و بانک/SMS واقعی در این تسک آزموده نشده‌اند.

اجرای نهایی محلی: backend 230 تست / 1563 assertion موفق؛ مرورگر Edge 156 با 49 بررسی موفق در چهار عرض و سه نقش، بدون خطای JS/CSP. کیبورد، reset، fieldset disabled و همگامی شرطی در این اجرای نهایی پوشش دارند. تصاویر با animation غیرفعال ثبت و خوانایی تقویم و چیدمان دسکتاپ/موبایل بازبینی شد. نتایج CI/MySQL/بسته در PR ثبت می‌شوند.

بازبینی تکمیلی فرم‌ساز: change مربوط به input جستجوی داخلی نباید schema/شرط‌ها را بازسازی کند. listener فرم‌ساز فقط کنترل‌های نام‌دار واقعی و فرم خصوصی فقط data-answer را پردازش می‌کند؛ انتخاب شرط وابسته در فرم‌ساز دو فیلدی به تست مرورگر اضافه شد.

پس از اصلاح تکمیلی listener فرم‌ساز، اجرای محلی نهایی مرورگر با 50 بررسی موفق شد. اجرای 49 بررسی پیشین مربوط به قبل از افزوده‌شدن سناریوی شرط وابسته است.
