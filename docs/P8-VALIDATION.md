اسناد AI_RULES/PRD/ARCHITECTURE/COMPONENTS/UI_GUIDELINES/SECURITY/DEPLOYMENT و وضعیت GitHub بازبینی شدند. PRهای ۱ تا ۷ همگی open/draft و merge‌نشده بودند؛ مبنا P7 commit `3de6128f4bf38e2ad04224c45c8e9f406acbe43f` و CI موفق شماره ۲۴ بود. اجرای پایه محلی مستقل: **۱۹۶ تست / ۱۳۳۶ assertion موفق** SQLite. sources/ و main تغییر نکرده‌اند. هیچ merge انجام نشده است.

## نتایج مشاهده‌شده

- تست‌های تازه HTTP production، رمزنگاری، بسته و readiness: **۱۵ تست / ۸۷ assertion موفق**. HTTPS/Host جعلی، پراکسی غیرمجاز و wildcard، cookie ناامن/debug، no-store خطا، redaction عمومی/SQL ورود، CSRF و استثنای محدود callback، کلید غلط/خرابی/حذف/الحاق/ترتیب آرشیو، traversal، بسته حاوی env/runtime/کلید/PDF/Excel و heartbeat کهنه پوشش دارند.
- مجموعه کامل SQLite در این مرحله: **۲۱۱ تست / ۱۴۲۱ assertion موفق**؛ Composer validate --strict و audit --locked --no-dev موفق، بدون advisory گزارش‌شده. نتیجه هر تغییر بعدی فقط پس از اجرای واقعی به نسخه نهایی نسبت داده می‌شود.
- بازیابی واقعی با mysqldump/mysql 8.4.3 روی سه دیتابیس مقصد موقت: **۳ تست / ۲۳ assertion موفق** در اجرای اولیه. dump رمزگذاری‌شده و فایل خصوصی بازیابی شدند؛ رسید ۸۰۰٬۰۰۰ ریالی، اعتبار ۸۰۰٬۰۰۰ ریالی، نوبت‌ها، ciphertext فرم و رمزگشایی پاسخ با APP_KEY اصلی حفظ شدند. خرابی انتهای archive پیش از اولین جدول مقصد رد شد؛ APP_KEY اشتباه و DB فعال/غیرخالی رد شدند. سپس مقایسه کامل کنترل تطبیق قبل/بعد هم به آزمون نهایی اضافه شد؛ نتیجه مجموعه نهایی جدا ثبت می‌شود.

بازبینی بعدی، حساب restore را به حساب مجزا و محدود به مقصد ارتقا داد. اجرای میانی Integration با fixture قدیمیِ فاقد credential مجزا شکست خورد: ۴۳ تست / ۳۰۰ assertion، یک error و یک failure؛ این اجرا موفق گزارش نمی‌شود. fixture به حساب‌های موقت دارای grant فقط مقصد تغییر کرد. بازاجرای واقعی بازیابی نهایی: **۵ تست / ۳۰ assertion موفق**، شامل مقایسه کامل تطبیق قبل/بعد، رد حساب دارای مجوز DB فعال و فایل SQL با رمزنگاری معتبر اما دستور USE/UPDATE روی DB فعال. سرور دسترسی را رد کرد و تعرفه DB فعال تغییر نکرد؛ مقصد نیمه‌کاره فعال نشد.

مجموعه کامل MySQL میانی پیش از دو assertion تازه منع خروجی PDF/Excel: **۲۱۱ تست / ۱۴۲۱ assertion موفق**. Pint با cache تازه، syntax ۲۰۳ فایل PHP در اجرای آن نسخه، Blade cache/clear و audit نیز موفق بودند. کنترل IP پراکسی پس از بازبینی به قاعده مشترک Domain منتقل و به readiness هم اضافه شد؛ اجرای نهایی شامل آن است.

## نصب مستقل و بار محلی

یک کپی مستقل خارج Git با وابستگی production-only، MySQL جدا `ani_doctor_p8_smoke`، APP_ENV=production/debug=false، session/cache دیتابیسی، APP_KEY تصادفی ساختگی و SMS/gateway خاموش نصب شد. migration/seed، optimize و schedule:run واقعی موفق و هر ۱۲ کنترل ops:check pass شدند؛ ready فقط پیکربندی محلی است. به env/credential هاست خارجی دسترسی داده نشده است.

Apache 2.4.66 ویندوز و چهار PHP-CGI 8.4.27 روی loopback، DocumentRoot فقط public و HTTPS با گواهی localhost و CA صریح cURL؛ هیچ -k یا غیرفعال‌کردن بررسی TLS و rate limit وجود ندارد. درخواست‌ها بدون کنترل مرورگر و صرفاً برای آزمون برنامه‌اند. ابزار openssl.exe نصب موجود خطای DLL داشت؛ گواهی مصنوعی با OpenSSL PHP ساخته شد. Apache محلی هشدار اختلاف نسخه compile/runtime OpenSSL داشت؛ این محیط گواه تأیید TLS هاست عمومی نیست و اجرای Linux CI جداگانه لازم است.

اجرای اول smoke و بار ناموفق بود: PHP-CGI ویندوز نگاشت فایل FastCGI را نمی‌خواند و همه پاسخ‌ها 404 بودند. نگاشت مسیر واقعی index.php فقط در تنظیم آزمایشی مستقل اصلاح شد؛ پاسخ‌های خطا موفق شمرده نشدند. اجرای بعدی:

- smoke: **۱۱ کنترل موفق**؛ login/up=200، مدیریت مالی/گزارش=302 ورود، env/vendor/storage/config/source=404، Host نامعتبر=421 و POST بدون CSRF=419.
- fixture: یک خدمت، شیفت‌های هفتگی، **۱۰۵۰ نوبت ساختگی** (۱۰۰۰ سابقه و ۵۰ نوبت آینده با بیماران مستقل)، هیچ پرداخت/پیامک واقعی.
- بار: **۴ هم‌زمان، ۴۸ درخواست، صفر خطا، ۰٫۷۷ ثانیه**؛ روز: p50=35.44ms، **p95=132.79ms**، max=134.86ms؛ ماه: p50=81.51ms، p95/max=85.28ms. هدف p95 روز ≤1000ms در این محیط گذشت. این اعداد تضمین بار اینترنت/هاست یا ظرفیت کاربران واقعی نیستند.

## موارد پایان‌نیافته و محدودیت پذیرش

اولین CI P8 [شماره ۲۶](https://github.com/anishopmobile/ani-doctor/actions/runs/40267860629) روی 55ba840 ناموفق بود: ۲۱۰ تست موفق و یک شکست در fixture قدیمی CSRF مربوط به P6؛ fixture حالت production داشت اما APP_URL پیش‌فرض CI از نوع HTTP بود و ProductionGuard پیش از CSRF پاسخ 503 داد. fixture با origin و درخواست HTTPS و cookie امن هماهنگ شد؛ guard ضعیف یا دور زده نشد. مراحل MySQL/بسته/staging آن اجرا skip شدند و artifact جدید منتشر نشد.

نسخه ثابت نهایی محلی: **SQLite ۲۱۱ تست / ۱۴۲۳ assertion موفق** و **مجموعه کامل MySQL Integration برابر ۴۵ تست / ۳۲۱ assertion موفق**؛ ۴۰ سناریوی رقابتی قبلی و ۵ سناریوی بازیابی محدود به مقصد در همان اجرا گذشتند. syntax نهایی **۲۰۳ فایل PHP بدون خطا**، Pint با cache تازه و Blade cache/clear موفق بودند. MySQL Feature میانی ۲۱۱/۱۴۲۱ بود؛ دو assertion آخر مربوط به رد PDF/Excel در بسته‌اند و نتیجه MySQL کامل نسخه نهایی را CI جدا ثبت می‌کند.

CI جدید، نصب همان ZIP در Linux staging موقت و مجموعه کامل نهایی MySQL/رقابت پس از پایان واقعی در PR ثبت می‌شوند؛ صرف وجود workflow به معنی موفقیت نیست. هیچ هاست/دامنه خارجی، پرداخت/SMS sandbox واقعی، دستگاه فیزیکی/چاپ، zoom 200٪، نفوذ مستقل، بازیابی off-site تولیدی یا بررسی حقوقی/حریم خصوصی انجام نشده است. رابط محصول در P8 تغییر نکرده و بررسی بصری تازه مرورگر ادعا نشده است. نمونه‌ها، DB، کلیدها، لاگ و runtime بیرون Git هستند.

پذیرش فنی staging موقت با انتشار عمومی متفاوت است؛ گیت‌های واقعی انتشار و مسئول عملیات در [P8.md](P8.md) ثبت شده‌اند. ابزار restore هرگز مقصد را فعال یا DB فعال را overwrite نمی‌کند؛ مقصد import ناموفق ممکن است نیمه‌کاره باشد و نیازمند تصمیم اپراتور است.
