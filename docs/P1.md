# P1 — زیرساخت و هویت

## محدوده و اثر

فقط P1: Laravel 13 / PHP 8.4، MySQL 8، نقش‌ها، OTP و پیش‌نیاز تأیید موبایل مهمان. مرجع: FR-AUTH-01، بخش تأیید موبایل FR-AUTH-02، BR-16، AC-AUTH در سطح هویت، NFR-01/03/04، SEC-01/02. رزرو و claim نوبت مهمان در P3 است؛ AC-AUTH در سطح نوبت هنوز قابل آزمون نیست.

- مالک: Identity؛ Patients فقط مدل مستقل و Policy مالکیت، بدون CRUD عمومی.
- جداول: users، roles، permissions، user_roles، permission_role، otp_challenges، sessions، identity_audit_events، patients، patient_user_links؛ cache/locks و jobs/failed_jobs/job_batches استاندارد Laravel.
- مسیرها: GET /login، POST /otp/request، POST /otp/verify، POST /logout، GET /dashboard و صفحات پایه /patient، /secretary، /admin. گروه web/session با CSRF.
- UI: Blade، Bootstrap RTL، Tabler، Vazirmatn محلی، JavaScript بدون build. پنل‌ها صفحه پایه دسترسی‌اند؛ داشبورد عملیاتی مربوط به P5 است.
- مجوز: Gate برای panel.patient/secretary/admin؛ Policy بیمار فقط پیوند صریح patient_user_links را می‌پذیرد. موبایل مشترک مالکیت نیست. نقش doctor وجود ندارد.

## نصب آزمایشی

PHP 8.4، extensionهای Laravel، Composer و MySQL 8 روی محیط خالی:

```sh
composer install
cp .env.example .env
# تنظیم دیتابیس آزمایشی و پیامک در .env
php artisan key:generate
php artisan migrate --seed
php artisan identity:provision-staff <mobile> admin
```

فرمان آخر فقط از کنسول مورد اعتماد اجرا شود؛ secretary نیز مجاز است. Seeder هیچ حساب یا رمز پیش‌فرضی نمی‌سازد. تخصیص نقش audit دارد، نشست‌های فعلی را حذف می‌کند و موبایل را تأیید نمی‌کند؛ ورود OTP لازم است. کاربر غیرفعال دسترسی ندارد. مدیریت کامل نقش‌ها خارج از P1 است.

پیش‌فرض production و کوکی Secure است. فقط برای localhost با HTTP: APP_ENV=local، APP_URL=http://127.0.0.1:8000 و SESSION_SECURE_COOKIE=false؛ سپس `php artisan serve --host=127.0.0.1`. این تنظیمات برای هاست عمومی نیستند. هیچ migration خودکار در request یا استخراج ZIP وجود ندارد.

## قرارداد احراز هویت

POST /otp/request دارای mobile (قالب ایران، تبدیل ارقام فارسی/عربی) و purpose=login|guest است. پاسخ HTML هدایت به فرم است؛ challenge فقط در نشست سمت سرور نگهداری می‌شود. OTP تصادفی ۶ رقمی فقط به شکل hash ذخیره می‌شود؛ اعتبار ۱۲۰ ثانیه، cooldown برابر ۶۰ ثانیه، حداکثر ۵ تلاش. سقف ارسال هر موبایل ۵ بار در ساعت و هر IP ده بار در دقیقه؛ verify هر IP بیست بار در دقیقه. کلید cache موبایل HMAC است. cache پیش‌فرض database و مشترک بین پردازه‌هاست؛ array فقط تست.

POST /otp/verify فقط code را می‌گیرد؛ موبایل، purpose و challenge از نشست می‌آیند. ورودی role یا موبایل دیگر اجازه ارتقای دسترسی ندارد. خطاهای verify یکسان‌اند. خطا پس از commit صادر می‌شود تا شمارش تلاش rollback نشود. resend کد قبلی را باطل می‌کند. قفل ردیف پایدار موبایل InnoDB صدور و مصرف را سری می‌کند؛ شبکه بیرون از قفل است. وضعیت sending/failed قابل ورود نیست. خطای Provider بدون متن خام، OTP یا کلید نمایش داده می‌شود.

حساب جدید/بی‌نقش فقط patient می‌گیرد. ورود و خروج شناسه نشست را تغییر می‌دهند؛ خروج نشست و CSRF token را باطل می‌کند. guest فقط تأیید ده‌دقیقه‌ای شماره در نشست می‌گیرد، بدون ایجاد حساب/بیمار و بدون دسترسی به داده قبلی. claim نوبت نیازمند پیاده‌سازی P3 است.

کد در old input یا log قرار نمی‌گیرد. صفحات no-store، CSP محلی، nosniff و منع embed دارند. زمان UTC و timezone نمایش Asia/Tehran است. کد منقضی بدون scheduler نیز رد می‌شود؛ `identity:prune-otp` ساعتی hashهای منقضی را پاک می‌کند و ردیف قفل/cooldown را نگه می‌دارد.

## SMS.ir

SMS_IR_API_KEY، SMS_IR_OTP_TEMPLATE_ID و SMS_IR_OTP_PARAMETER در محیط سرور تنظیم شوند. adapter از endpoint ثابت `https://api.sms.ir/v1/send/verify` و [قرارداد رسمی](https://github.com/IPeCompany/smsir-php/blob/main/src/SmsIrService.php) استفاده می‌کند. پورت P1 فقط sendOtp دارد؛ اعلان/پیگیری تحویل برای P6 است. timeout و خطای HTTP/status ورود را مسدود می‌کند. retry شبکه خودکار نیست چون timeout ممکن است بعد از تحویل رخ دهد. تست‌ها fake هستند؛ اتصال واقعی و تحویل پیام نیازمند آزمایش با حساب SMS.ir است.

## تست و rollback

```sh
composer validate --strict
vendor/bin/pint --test
php artisan test --without-tty
# فقط دیتابیس MySQL آزمایشی دورریختنی:
DB_CONNECTION=mysql vendor/bin/phpunit -c phpunit.mysql.xml
```

در PowerShell متغیرها با `$env:` تنظیم شوند. suite هم‌زمانی دو پردازه PHP مستقل را پشت مانع شروع هماهنگ می‌کند و فقط MySQL می‌پذیرد؛ migrationهای تست داده را حذف می‌کنند. SQLite اثبات رفتار قفل MySQL نیست. CI همچنین migrate/rollback/migrate را روی MySQL دورریختنی اجرا می‌کند. نتیجه واقعی: [P1-VALIDATION.md](P1-VALIDATION.md).

Rollback جداول هویت/بیمار/نشست‌ها را حذف می‌کند؛ برای داده واقعی مخرب و نیازمند بکاپ و بررسی است. بسته P1 سامانه کامل نوبت‌دهی نیست. استقرار عمومی، آزمون بار، بازیابی بکاپ، 2FA کارکنان و سخت‌سازی نهایی P8 در این فاز ادعا نمی‌شود.
